# memefwd — 밈코인 필터 포워드 테스트 (페이퍼, 실매수 없음)

@savipww 가이드의 하드필터·체인필터를 재현해서, 필터를 통과한 토큰(pass)과 탈락한 토큰(control)의 이후 수익률과 러그 비율을 2주간 비교합니다.
LLM(Jev) 판단은 뺐습니다. 하드필터에 엣지가 없으면 그 위에 LLM을 얹을 근거도 없기 때문입니다.

## Railway 배포

1. 이 폴더를 GitHub 새 저장소에 올린 뒤 Railway에서 **New Project → Deploy from GitHub repo**를 선택합니다.
   (또는 이 폴더에서 `railway init` → `railway up`)
2. 서비스 우클릭 → **Attach Volume**을 선택하고, Mount path를 `/data`로 지정합니다.
   **이 단계를 빠뜨리면 재배포할 때마다 데이터가 날아갑니다.**
3. Variables에 추가합니다.
   - `REPORT_TOKEN` = 아무 긴 문자열 (리포트 URL 보호용)
   - (선택) `NETWORKS=solana,bsc,robinhood`, `GT_RPM=9`
4. Settings → Networking → **Generate Domain**을 누릅니다.
5. 리포트 확인
   - `https://<도메인>/?key=<REPORT_TOKEN>` : 리포트
   - `https://<도메인>/export.csv?key=<REPORT_TOKEN>` : 원자료 CSV

## 동작

- 15분마다 GeckoTerminal에서 체인별 신규 풀 40개를 가져와 관찰 목록에 등록합니다.
- 각 풀은 상장 후 20분, 45분, 1.5h, 3h, 6h, 12h, 24h, 48h, 72h 시점에 재평가합니다.
- 평가 순서
  1. 하드필터: 나이, 유동성, 거래량, 시총, 거래수, 매도 없음 여부
  2. 체인필터: 홀더, top10, top지갑, 권한, 허니팟
- 처음으로 통과한 시점의 가격을 pass 진입가로 기록하고, 24시간 동안 15분 간격으로 추적합니다.
- 처음 평가 가능한 나이에 탈락한 토큰의 35%를 대조군(control)으로 삼아, 1h·6h·24h 시점 가격을 기록합니다.
- 리포트에는 사전 합격 기준 C1~C4가 자동으로 판정되어 표시됩니다. 기준은 시작 전에 고정한 것이니 결과를 보고 바꾸지 않습니다.

## 알려진 한계

- 진입가는 GeckoTerminal 중간가입니다. 실제 체결 슬리피지는 왕복비용 3% 가정으로만 반영했습니다.
- 가격 추적 해상도는 15분입니다. 그 사이에 일어난 급락은 보이지 않으므로 손절 시뮬레이션은 낙관적입니다.
- `robinhood` 네트워크 ID가 GeckoTerminal에서 다르면 자동으로 제외되고, 리포트에 경고가 표시됩니다.

## 후보 필터 탐색 (B항목 추가분)

- 평가할 때마다 GeckoTerminal 원자료를 `checks.extra`에 함께 저장합니다. 고유 매수자·매도자 수, 5분 거래·거래량·등락이 들어갑니다. 필터 판정에는 쓰지 않고 기록만 합니다.
- 신규 풀을 수집할 때마다 시장 분위기(상장 속도, 신규 풀 거래량·등락 중앙값)를 `regime` 테이블에 기록합니다.
- `https://<도메인>/analyze?key=<토큰>&train=3&test=3` : 앞 3일에서 필터를 고르고, 뒤 3일에서 확인한 결과를 보여줍니다.
- 기존 DB는 그대로 유지되고, 새 컬럼만 자동으로 추가됩니다.

## pass2 (수정 규칙) — 가이드 원본(pass)과 나란히 판정

| | pass (가이드 원본) | pass2 (수정) |
|---|---|---|
| 값이 비어 있을 때 (홀더 수, top10, Solana 최대지갑, BSC 허니팟) | 그 조건을 건너뜀 (통과 처리) | **탈락** (`missing_*`) |
| Solana 최대 지갑 5% 규칙 | 가장 큰 토큰계정 그대로 (보통 유동성 풀 자체) | **풀 금고·락업 등 프로그램 소유 계정(PDA)을 제외**하고, 실제 지갑 기준으로 소유자별 합산 |

- 하드필터와 평가 시점은 두 그룹이 똑같습니다. 같은 데이터로 동시에 판정합니다.
- 합격기준 C1~C4는 두 그룹에 각각 따로 적용됩니다.
- pass2는 이 버전을 배포한 시점부터 기록됩니다. 리포트에 시작 시각이 표시됩니다.

## LP(유동성) 안전성 기록 — 러그풀 분석용 (필터 판정에는 아직 안 씀)

- EVM 체인(BSC·Base·Robinhood)에서 하드필터를 통과한 토큰에 대해 두 가지를 기록합니다.
  - RPC로 V2 풀의 LP 중 소각 주소(0xdead·0x0)에 있는 비율
  - GoPlus로 LP 보유자 수·락 여부, 제작자 보유율, 매수·매도 세금, 권한 위험 플래그
- 리포트의 "LP 상태별 러그 비율"에서 LP 소각·락 비율과 LP 제공자 수에 따라 러그 비율이 어떻게 다른지 봅니다.
- 로그와 리포트에 토큰 주소(CA)를 표시합니다. 예전에는 풀(LP) 주소만 찍혀서 BSC에서 Cake-LP로 보였습니다.
- 선택 변수: `BSC_RPC`, `BASE_RPC`, `ROBINHOOD_RPC`, `GOPLUS_RPM`(기본 20)

## 거래 흐름(C항목) · 러그 속도 · 대박 토큰 해부

- 하드필터를 통과한 토큰마다 최근 체결 최대 300건을 조회해 기록합니다. 기록만 하고 판정에는 쓰지 않습니다.
  - 고유 지갑 수, 지갑당 거래 수
  - 상위 5지갑 거래량 비중
  - 사고팔기를 반복한 지갑 비율(자전거래 의심)
  - $2 미만 먼지 거래 비율
  - 같은 블록 묶음 매수 비율(번들)
  - 순매수 흐름
- 리포트 "러그는 얼마나 빨리 오나": 러그까지 걸린 시간의 분포를 보여줍니다.
- 리포트 "살아남은 뒤 진입": 통과 후 1·2·3·6시간 기다렸다가 러그가 안 났을 때만 진입해 6시간 보유한 성적입니다.
- 분석 화면 "대박 토큰 해부": 6시간 +50% 이상 오른 토큰과 나머지를 진입 시점 특징으로 비교합니다(AUC). `WINNER_THR` 변수로 대박 기준을 바꿀 수 있습니다.

## v8 — 생존자 전략 검증

- **BSC 신규 수집을 중단했습니다.** 기본 `NETWORKS=solana,robinhood`. 이미 진입한 BSC 건의 가격 추적은 계속합니다.
  - Railway 변수에 `NETWORKS`를 직접 넣어두셨다면 삭제하거나 `solana,robinhood`로 바꾸세요.
- 신규 풀 수집을 다시 체인당 40개(2페이지)로 늘렸습니다.
- 가격 데이터 의심값(한 구간 +1000% 초과)은 평균·신뢰구간 계산에서 빼고, 제외 건수를 따로 표시합니다.
- pass와 pass2에 같은 토큰이 중복으로 들어가던 것을 정리했습니다. 이제 러그 속도와 대기 진입 계산은 고유 토큰 기준입니다.
- 살아남은 뒤 진입: 대기 1·3·6·12시간 × 보유 6·12시간 조합으로 봅니다.
- 생존자 전략 상세(12h 대기·6h 보유)
  - 진입 시점 6h 거래량이 $5,000 이상인 "활성" 토큰과 그 미만인 "좀비" 토큰을 나눠 봅니다.
  - 체인별 결과를 따로 보여줍니다.
  - 사전 기준 S1~S4를 자동 판정합니다. 기준은 v8 첫 실행 시각에 고정되며, 리포트에 그 시각이 표시됩니다.
- 가격 추적 기간을 24시간에서 30시간으로 늘렸습니다.

## v9 — 생존자 확장 (하드필터 통과 토큰 전체)

- 생존자 전략은 가이드 체인필터(top10·홀더 등)와 상관이 없습니다. 그래서 하드필터(유동성·거래량·시총·거래 수)를 처음 통과한 토큰을 **전부** 추적합니다.
- 추적 시점: 통과 후 3·6·12·18·24시간
- 12시간까지 러그가 없으면 12시간 시점 가격에 진입한 것으로 봅니다. 성적은 6시간 보유와 12시간 보유 두 가지로 계산하고, 활성/좀비와 체인별로 나눠 보여줍니다.
- 기준 T1~T4는 S1~S4와 같은 내용입니다. 대상은 활성 토큰·6시간 보유이고, v9 첫 실행 시각에 고정됩니다.
- 이 데이터는 v9 배포 이후 통과한 토큰만으로 계산됩니다. 과거 결과를 보고 만든 기준이 아니므로 표본 밖 검증이 됩니다.
